AI document extraction, schema mapping and bank reconciliation

The problem

Financial documents and ledger exports all lay out and name their data differently. Before two sets of figures can be reconciled, someone has to key the data in, work out what each column means, clean the cells and line the files up. That was done by hand each time.

What I built

One pipeline that takes a raw document through to a finished reconciliation, and explains each decision it makes on the way.

How it works

  • Extraction: optical character recognition turns each page into text with its position, and a language model finds the tables and works out the column names from the document itself, instead of a fixed template per layout. The same step drafts training labels for a custom extraction model, which a person reviews instead of drawing by hand.
  • Profiling measures every column: types, distinct values, patterns.
  • Mapping decides what each column is from its name and its values, with a confidence score. Uncertain mappings become proposals for a person, and every decision is written to an audit log.
  • Quality parses real-world cells such as "1.234,56", "(500)" and "12/03/25", and records each repair.
  • Reconciliation matches lines with ranked rules, then explains every line left alone: bank charges, outstanding cheques, duplicate entries.
  • Attribution works backwards from a broken balance to the cell or decision that caused it. Impact shows what would change if a rule were switched off or reordered, and learning proposes new rules from labelled data.
  • Discovery engine: given a set of related tables, it works out from the values alone, not the column names, which keys link them, which numbers are computed from which, which rules decide a value, which cells are wrong and what they should be. Each finding is presented as a case with the evidence for and against, and an LLM is asked only where the data cannot settle a question. Every run is stored in PostgreSQL, one schema per step, so it can be reviewed later.
  • Testing: a generator produces bank statements and cash books with a known correct answer, adds noise at controlled rates, and sweeps the rates to find where the pipeline breaks.

AI assistant for internal CRM tools

The problem

Day-to-day CRM work means reading long email threads and clicking through many screens to look up or update records, one at a time.

What I built

An assistant that lets staff work with the company CRM in plain language.

How it works

  • Email summaries: condenses a long thread into key points, open questions and next actions.
  • Plain-language requests: turns a request into the matching CRM lookups and updates.
  • Parallel runs: runs several tasks against the system at the same time, so a batch of records is handled in one go.
