AI-assisted document analysis

A team of 12 became a team of 3.

The problem

Reading financial documents and keying their contents into a system is slow, repetitive work, and every supplier and bank lays its documents out differently. The work needed twelve people.

What I built

A workflow in which language models read the documents and extract the data, so people check results instead of typing them. Large and small models each do the part they are good at.

How it works

  • Optical character recognition turns each page into text with its position on the page.
  • A language model finds the tables and works out the column names from the document itself, instead of relying on a fixed template for each layout.
  • The same step drafts the training labels for a custom extraction model, which a person reviews instead of drawing by hand.

Schema mapping and bank reconciliation pipeline

The problem

Before two financial files can be reconciled, someone has to work out what each column means, clean the cells, and line the two files up. Every bank and ledger export is different, so that work was done by hand each time.

What I built

A pipeline that takes a raw file through to a finished reconciliation statement, and explains each decision it makes on the way.

How it works

  • Profiling measures every column: types, distinct values, patterns.
  • Mapping decides what each column is from its name and its values, with a confidence score. Uncertain mappings become proposals for a person, and every decision is written to an audit log.
  • Quality parses real-world cells such as "1.234,56", "(500)" and "12/03/25", and records each repair.
  • Reconciliation matches lines with ranked rules, then explains every line left alone: bank charges, outstanding cheques, duplicate entries.
  • Attribution works backwards from a broken balance to the cell or decision that caused it.
  • Impact shows what would change if a rule were switched off or reordered, and learning proposes new rules from labelled data.

Python · Polars · Pydantic · Pandera · about 19,000 lines · 219 unit tests

PersonalData collection · law

Vietnamese legal database

The problem

Vietnamese court judgments and the laws they cite are published on separate government sites, mostly as documents meant for reading. Nothing links a judgment to the exact articles it relies on.

What I built

A pipeline that collects published judgments by case category, extracts the laws and articles each one cites, then downloads that legislation and stores both in one database. It draws on my law degree as much as on my data work.

How it works

  • Three steps that skip work already done, so the pipeline is safe to rerun.
  • Legislation is stored in its real structure, from part and chapter down to article, clause and point.
  • Judgments are stored with their court, parties, panel and citations, linked to the cited articles.
  • A wrong match cannot slip in: a downloaded law is refused if its document number differs from the citation.

Python · PostgreSQL · SQLAlchemy · public sources only

PersonalAutomation · security

Channel Manager

The problem

Publishing the same video to YouTube, TikTok and Facebook means three uploads and three schedules. Most tools that automate it ask for your passwords.

What I built

A command-line tool that publishes and schedules from one queue file, run automatically by Windows Task Scheduler. I designed it around security first.

How it works

  • It uses only the official APIs, and signs in through each platform's own login page. No password is ever stored.
  • It asks for the fewest permissions that work. Nothing it holds can delete a channel or a video.
  • Access tokens are encrypted on the device, and the key is protected by the Windows login.
  • Logs are stripped of secrets before they are written.

Python · YouTube Data API · TikTok Content Posting API · Facebook Graph API · OAuth with PKCE
